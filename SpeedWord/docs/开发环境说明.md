# 开发环境说明

## 环境要求

| 项目 | 版本 |
|---|---|
| Node.js | ≥ 18（建议 20 LTS） |
| npm | ≥ 9 |
| 操作系统 | Windows 10/11（开发与打包均在 Windows 上完成；一体机为 Windows） |
| 硬件 | 无需独立 GPU；无需安装 Ollama / 大模型 |

本项目不依赖本地大模型，SQLite 使用 sql.js（WASM）在浏览器引擎内运行，无需编译原生扩展，低配 Windows 一体机可直接运行。

## 安装依赖

```bash
npm install
```

### 中国大陆网络镜像（重要）

Electron 与 electron-builder 需要下载二进制，国内直连常超时。推荐设置：

```bash
# PowerShell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npm install

# 若 node_modules 已装坏，先删掉重装：
#   Remove-Item -Recurse -Force node_modules ; npm install
```

> 提示：也可以在用户环境变量里永久设置上述两个变量（系统设置 → 环境变量），一劳永逸。

## 常用命令

```bash
npm start          # 完整构建并启动 Electron（开发）
npm run dev        # 同 start
npm run test       # vitest 67 项纯逻辑单测（node 环境，无需 Electron 窗口）
npm run test:watch # 监听模式
npm run typecheck  # vue-tsc 类型检查
npm run build      # prepare:assets + 编译主进程 + 构建渲染端
npm run dist:win   # 完整构建 + 生成 Windows NSIS 安装版 + Portable 绿色版（release/）
npm run dist:portable
npm run clean      # 清理构建产物
```

## 三个构建阶段的产物

| 脚本 | 产物 | 说明 |
|---|---|---|
| `prepare:assets` | `assets/` 校验、`dist/` 准备 | 检查内置词典/图片存在，必要时补齐 |
| `build:electron`（tsc `tsconfig.electron.json`） | `electron-dist/` | 主进程 TS→CJS，并复制 `sql-wasm.wasm` |
| `build:renderer`（vite） | `dist/renderer/` | Vue 渲染端（约 150 KB JS，gzip 约 55 KB） |

## 项目分层与共享逻辑

渲染端与主进程都会用到「纯逻辑」模块，放在 `src/shared/`：

- `types.ts` —— 全项目类型与常量（`ContentItem` / `WordPack` / `GAME_MODES` / `FeedbackSignal` 等）
- `api.ts` —— 渲染端可见的 `window.api` 类型（IPC 契约）
- `fieldstate.ts` —— 字段人工状态机 `auto / edited / locked`
- `type-detect.ts` —— 内容类型识别
- `ipa.ts` —— 内置词典查询
- `game/state-machine.ts`、`game/queue.ts`、`game/question.ts` —— 课堂引擎
- `sqljs.d.ts` —— sql.js 最小类型声明

主进程（`electron/`）编译为 CommonJS，渲染端（`src/`）由 Vite 编译。**两边各自依赖自己的构建链**，任何改动都要分别 `npm run build:electron` 与 `npm run build:renderer` 验证。

## 测试说明

```bash
npm test
```

67 项测试覆盖：类型识别（10）、字段状态与合并保护（8）、课堂状态机（8）、出题队列与干扰项（12）、8 玩法出题（9）、IPA 查询（9）、备份导入/导出/回滚与全量 dump-restore（5）、AI 结果合并（6）。

测试设计要点：

- 测试目标为 `src/shared/**` 与 `electron/**` 的**纯函数/数据层**，跑在 vitest `node` 环境，**不需要启动 Electron**。
- `electron/db.ts`、`electron/backup.ts` 依赖 `electron` 模块：测试用 `vi.mock("electron", factory)` 提供桩（`dialog` / `app`），并用 `SPEEDWORD_USER_DATA` 环境变量把素材写入临时目录，从而用**真实的 sql.js** 跑数据库往返。
- 覆盖「非法转移拒绝 / 锁机制」等快速连点与动画保护逻辑 —— 对应验收点 #10。

## 常见问题

**Q: `npm install` 卡在 electron 下载。**
A: 设置上文两个镜像变量后重装。

**Q: `npm start` 白屏或 `sw://` 图片不显示。**
A: 确认已执行过 `npm run build`（`sw://img/` 协议由主进程在 `dist/renderer` 存在时注册）。

**Q: 改完 `src/shared/` 后测试通过但运行不对。**
A: 共享逻辑被主进程与渲染端各编译一次，请重新 `npm run build`（含 electron 编译）再启动。

**Q: typecheck 报 `sql.js` 无类型声明。**
A: 已内置 `src/shared/sqljs.d.ts`，确认它存在于 include 路径内（`src/shared/**/*.ts` 覆盖）。
